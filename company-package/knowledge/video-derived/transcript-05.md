# Transcript 05 — design judgment brain

## Source contribution
The source describes a source-cited, markdown/Obsidian-style design brain that combines several frontend design practices into one advisory layer and grows over time. The point is not one magic design prompt, but a curated body of design judgment that agents can consult when producing landing pages, blogs and interfaces.

## Verified upstream
The user identified the exact project as `AgriciDaniel/gogh`: https://github.com/AgriciDaniel/gogh.

Repository inspection confirms that Gogh is an Apache-2.0 source-cited Obsidian operating brain for six frontend design skills. It does not flatten the six skills into one prompt. It separates mechanisms such as aesthetic direction, micro-interaction execution, toolchain enforcement, retrieval and audit, then advises which layers to use for a given brief. The repository also keeps dated source evidence, preserves conflicts between upstream skills, keeps raw captures immutable and exposes explicit maturity/audit gates.

Two especially useful patterns for Founder OS are:

1. Direction before generation. Gogh requires a written aesthetic-direction commitment before implementation so a page has a specific visual thesis and signature element rather than merely complying with anti-slop rules.
2. Distinctiveness as an exit gate. Mechanical correctness is treated as a floor. Client-facing work must also be memorable and meaningfully different from a generic competitor-swappable template.

## Founder OS adaptation
Use Gogh as an optional advisory source for fake doors, landing pages and campaign surfaces. Founder OS keeps its own `design-judgment-stack` skill, but that skill now follows the same high-level discipline: source-cited rules, explicit direction before implementation, mechanism-aware selection rather than loading every rule blindly, conflict preservation, preservation checks for redesigns, and a distinctiveness review before an asset is approved.

Generated design directions must still serve the experiment's audience, offer, CTA and measurement plan. Design quality does not count as market validation.

## Boundary
Gogh is not vendored or automatically installed. It is an optional upstream capability and must be re-checked at pilot time. Its design judgments and practitioner findings are not silently promoted into universal business truth, and no credentials or private venture data should be copied into an external design vault.
